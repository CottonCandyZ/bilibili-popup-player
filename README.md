# Bilibili Popup Player - Nano

默认使用哔哩粉。设置中的「主题配色」提供哔哩粉、哔哩蓝、黑白和自定义强调色，可使用取色器或输入十六进制色值。配色同步作用于小窗的开关、选中状态、播放器和评论，不影响原页面。

播放器工具栏使用 Lucide 图标，叠在画面上方，显隐与淡入淡出跟随原生播控；悬停控件、键盘聚焦或菜单打开时保持可见。侧栏保留评论、合集 / 分 P、播放列表、相关推荐等原有标签，使用下划线区分当前标签；切换标签不会卸载评论，再次点击选集、播放列表或直播列表的当前标签会定位正在播放的条目。列表填满可用高度，在画面下方时最多占用视口高度的 65%（上限 640px）。播放量和弹幕保留原版 SVG，正在播放的条目显示固定尺寸的 SVG 动画。

窗口布局和手柄快捷键统一放在设置中，字号、行高和图标位置与开关行对齐，快捷键可在菜单内展开。侧栏模式的收起、关闭按钮位于标签栏右端；下方评论和迷你模式中回到视频内，按设置、收起、关闭排列。侧栏标签采用 34px 高度与 12px 字号，切换时只让当前面板参与布局。

侧栏评论立即请求，下方评论保留滚动到可见区域再加载的行为。列表滚动容器贴合侧栏边缘，内容留白放在容器内部；页面卡片优先提取标题节点，避免混入稍后再看提示、统计和预览文字。

下方内容采用播放页布局，不再显示标签栏：左边是视频简介和评论，右边依次显示选集、播放列表与推荐。窄窗口改为单列。UP 主头像和名字均可打开空间页。

评论、列表和播放区优先使用不占宽度的原生滚动条；浏览器滚动条占用布局宽度时，隐藏原生外观并改用悬浮滚动条，滚动时显示、停止约一秒后淡出，也支持拖动。不会在播放器边缘留下滚动条槽。

普通视频和番剧默认使用原生播放器的网页全屏模式，画面填满小窗内部，弹幕输入并入随鼠标显隐的控制栏，不再额外占用底部高度。原生宽屏按钮切换下方列表与右侧栏，切换时保留当前标签和播放实例。窗口按 16:9 适配；鼠标箭头静止时由原生播放器自动隐藏，移动后立即显示。点击遮罩即可关闭播放器，在播放器内开始拖动再移出不会误关。

方向键与空格由原播放器处理：左右短按快进 / 后退 5 秒，上下调整音量，空格暂停 / 播放，保留长按右方向键临时倍速、松开恢复原速的行为。快捷键不接管评论输入、设置菜单或标签栏的键盘操作。

控制栏按播放器实际宽度适配，窄窗口收起弹幕输入框并缩小控件间距。下方评论模式中，播放器先占满窗口首屏，向下滚动查看评论。网页小窗与独立小窗完全禁用滚轮调音量，包括音量控件和全屏状态；音量可通过点击或拖动调整。评论沿用原站组件与交互，正文为 13px、行高 21px，头像、回复缩进和操作栏采用紧凑排版，样式只作用于小窗内的评论。

视频完全滚出可视区域后，同一播放器会浮到右下角，评论保持可滚动；向上滚回视频或点击“回到视频”即可还原。手动收起和还原的动画期间暂时隐藏评论，尺寸按布局高度计算，不受动画缩放影响。

网页内全屏会记住用户选择：关闭后重新打开、收起后还原以及刷新页面后仍恢复对应状态，主动退出全屏后恢复普通窗口尺寸。进入和退出使用 300 毫秒缩放过渡，遵循系统的减少动态效果设置。

系统全屏包含整个网页小窗，保留顶部操作和侧栏 / 下方内容，隐藏画面底部常驻的细进度条。原生全屏按钮、F 键与双击画面均可切换，Esc 退出后回到原先的窗口状态。原生网页全屏按钮的图标和提示跟随小窗实际状态。

点播、番剧和直播播放页的画中画入口位于页面右下角、设置按钮上方。点击直接打开独立小窗；不支持 Document PiP 的浏览器中，点播与番剧入口回退为网页小窗。

拖动窗口右下角可以调整尺寸，角落不显示常驻图标。首次打开时提示一次，4 秒后自动消失；重新打开或刷新页面后不再提示。

画面上方的向下按钮可以将播放器收起到右下角，距离页面边缘 16px，保留同一个播放实例；收起后可继续滚动和浏览页面。迷你窗口保留设置、还原和关闭按钮。打开、关闭、收起和还原时，背景遮罩与模糊平滑过渡，并遵循系统的减少动态效果设置。

卡片入口只识别真实视频封面，包括历史记录、收藏浮层里的小封面，避开 OGV 选集格子、播放器内部与对话框。显示前检查鼠标位置、按钮区域的实际遮挡和滚动容器裁剪；页面切换、卡片复用或遮挡层变化时更新入口。鼠标离开后收起播放或跳转按钮，保留上次播放标记。

## 安装

访问 [pop-player.nanachi.moe](https://pop-player.nanachi.moe/)，按页面提示安装即可。

安装本地构建时，在 ScriptCat（脚本猫）或 Tampermonkey（油猴）中导入根目录的 `bilibili-popup-player-nano.user.js`，`dist` 中的同名文件也可使用。文件开头应为 `// ==UserScript==`；构建过程会验证这个元数据头，缺失时终止构建。

许可正文保存在独立文件中，脚本头仅保留 `@license` 标识。

独立小窗按 `documentPictureInPicture.requestWindow` 是否可用来启用，不按浏览器名称或版本屏蔽。Firefox 桌面版自 [151](https://www.firefox.com/en-US/firefox/151.0/releasenotes/) 起支持 Document PiP；接口不可用时仍可使用网页小窗。

## 本地调试

```sh
pnpm install
pnpm run dev
```

然后在用户脚本管理器里安装根目录的 `bilibili-popup-player-nano.dev.user.js`。这个 dev loader 会从 `http://127.0.0.1:8715/bilibili-popup-player-nano.user.js` 拉取本地 bundle；改动源码后 Rollup 会自动重建，已打开的 B 站页面会自动刷新。

## 验证

```sh
pnpm build
pnpm check
pnpm test
pnpm test:browser
```

浏览器回归使用本机 Chrome，也可通过 `PLAYWRIGHT_CHANNEL=msedge` 选择 Edge。测试覆盖 OGV 与历史浮层挂载、遮挡和裁剪、SPA 与卡片复用、总开关、键盘操作、光标与播放标记、切回窗口防误关、播放器比例、迷你窗口与独立小窗的生命周期。播放接口和媒体实例使用测试替身；真实媒体加载、账号权限及 Document PiP 行为仍需在 B 站页面验证。

pnpm run release

## 架构

- 共用卡片扫描、封面点击拦截、播放页 SSR 解析、主题 CSS、评论组件、调试入口。
- 设置入口和普通卡片按钮渲染在页面级 shadow overlay 中；历史记录等悬停浮层的按钮挂载到卡片内部的独立 shadow root，以保留浮层的悬停状态，销毁时清理挂载点和定位样式。
- `card-targets.js` 负责真实封面识别、可见区域与遮挡检测；播放页排除当前视频，OGV 选集不挂入口。
- `settings-ui.jsx`、`player-shell-ui.jsx` 和 `content-ui.jsx` 使用 Base UI 的 Popover、Switch、Radio、Dialog、Tabs 与 Button；`ui-theme.js` 统一样式。
- 评论组件保留在我们自己的 modal/PiP 容器内。
- 播放容器通过 renderer adapter 区分：
  - `homeRenderer`：当前网页内 modal / 右下角迷你播放器。
  - `pipRenderer`：支持 Document Picture-in-Picture 的浏览器独立小窗。
- 评论区统一走 `window.BiliComments`，切视频优先 `comment.methods.reload(props)`，否则 fallback 到 `dispatchAction({ type: "reload" })`。
